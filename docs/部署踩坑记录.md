# 18mu-blog 部署踩坑记录

本文只记录已验证的故障根因和处理方式。新记录必须包含发生条件、症状、根因、处理、验证和预防；不记录任何 Secret 实际值。

## 1. embedding 端点误用 API Key 记录编号

**症状**：Worker 部署成功，但 `npm run sync:knowledge` 返回 `502 {"error":"Embedding provider returned 400"}`。

**根因**：资源文件同时包含 API Key 记录编号和业务空间 ID；最初将记录编号误填到 `EMBEDDING_BASE_URL`，而 OpenAI-compatible URL 需要真实 workspace host。

**处理**：只读取资源文件中的 `workspaceId`、`apiHost` 或 `openAiCompatible`，不输出 `apiKey`。把完整 OpenAI-compatible base URL 配置到 `wrangler.toml`，保持 `qwen3.7-text-embedding` 和 `1024` 维度，然后重新部署并运行工作流。

**验证**：成功运行的同步日志输出 `{"updatedAt":"...","articleCount":2}`。

**预防**：Provider `400` 时先核对 workspace endpoint、模型名、维度和请求格式，不把 API key 打进日志。

## 2. GitHub Cloudflare API Token 失效

**症状**：Actions 在 `npx wrangler deploy` 失败，日志含 `Authentication error [10000]` 或 `Invalid access token [9109]`；同步步骤不会运行。

**根因**：GitHub `CLOUDFLARE_API_TOKEN` 失效、过期或权限不足。

**处理**：先以 `npx wrangler whoami` 确认本机登录；在 Cloudflare 创建专用最小权限部署 token，更新 GitHub Secret `CLOUDFLARE_API_TOKEN`，再手动运行 **Deploy to Cloudflare Workers**。

**验证**：同一工作流的 `npx wrangler deploy` 和 `npm run sync:knowledge` 都成功。

**预防**：使用专用 CI token，不用 Global API Key；设置到期提醒。完整权限见 `docs/Cloudflare 与 GitHub 配置手册.md`。

## 3. 本机 `npm run deploy` 不会同步知识快照

**症状**：页面已更新，但 `/map`、`/walk` 仍是旧关系或缺新文章。

**根因**：本机命令只构建并执行 `wrangler deploy`，不具备 `KNOWLEDGE_SYNC_TOKEN`，不会调用同步脚本。

**处理**：本机部署后，在 GitHub Actions 手动运行工作流，让它执行受保护的 `npm run sync:knowledge`。

**预防**：日常发布使用 `git push origin main`；不为本机同步把 token 写进 `.dev.vars` 或脚本。验收时查看 `articleCount`。

## 4. 本机网络无法直连 GitHub 或 workers.dev

**症状**：`Recv failure: Connection was reset`、`Empty reply from server`、`Failed to connect to github.com port 443` 或 `curl (28) Timeout`。

**根因**：本机网络短暂异常或当前环境策略限制；这不等于构建、Git、Worker 配置有问题。

**处理**：保留提交历史，重试 `git push origin main`；使用 GitHub Actions 状态和 `npx wrangler deployments list --name 18mu-blog` 作为权威部署证据。

**预防**：明确区分“本机已部署”“已推送”“Actions 成功”三种状态，禁止因单次网络失败重置仓库或重建资源。

## 5. 用 `file://` 打开 `.deploy` 时样式丢失

**症状**：直接打开 `.deploy/index.html` 显示无样式页面。

**根因**：站点资源是 `/_astro/*` 根路径；`file://` 没有 HTTP 根路由，不能模拟 Workers Static Assets。

**处理**：使用 `npm run dev`、`npm run preview` 或生产 URL 做视觉检查。

**预防**：静态产物存在只能证明构建成功；不能用 `file://` 截图判断视觉质量。

## 6. 内容关系校验失败

**症状**：`npm run validate` 报告 `relatedBlog references missing ...` 或关联未发布记录。

**根因**：关系字段是 Markdown 文件 slug，不是标题、URL 或标签。

**处理**：核对 `src/content/<collection>/` 的真实文件名，修正引用或先发布目标记录，然后运行 `npm run validate:relations`。

**预防**：slug 保持稳定；改名时用 `rg` 查找旧 slug 并更新所有关系。
