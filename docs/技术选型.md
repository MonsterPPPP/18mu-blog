# 18mu-blog 技术选型

- 框架：Astro + TypeScript，使用 Content Collections 校验 Markdown 内容。
- 样式：自定义 CSS 视觉系统；复杂的检索、认知地图和随机漫步使用 React Islands。
- 图谱：D3.js 负责浏览器端认知地图布局；语义关系由 Worker 生成，不由标签或手工关系替代。
- 内容：Astro Content Collections 是 Markdown frontmatter 的可执行契约。项目、经历与 For Agent 都拥有稳定详情路径；项目与经历的 slug 关联在构建时验证。
- 部署：Cloudflare Workers Static Assets，静态产物来自 `.deploy/`；Worker 同时提供受保护的同步端点和无密钥的公开语义快照端点。
- 自动发布：GitHub Actions 在 `main` 上运行关系校验、类型检查、构建、Wrangler 部署和知识快照同步。

Workers Static Assets 保持正文与索引静态化，同时允许后续添加 KV、同步 API 或边缘缓存而不迁移站点。本站不使用 CMS、登录、评论、数据库写作或 OpenAI/Workers AI 的固定绑定。

语义同步由 GitHub Actions 将 `published: true` 的博客 Markdown 发送至受保护 Worker 端点；Worker 通过 Cloudflare Secret 调用可替换的 embedding 提供方，生成可重建的向量、聚类、地图和漫步快照，并写入 Cloudflare KV。公开浏览器只读取 `/api/knowledge` 的无密钥派生数据。项目、经历和 For Agent 内容不会进入该同步过程。

当前生产地址为 `https://18mu-blog.15589866906.workers.dev`。模型服务采用 OpenAI-compatible embedding 协议：端点、模型名、维度为 Worker 环境配置，`DASHSCOPE_API_KEY` 与同步令牌仅作为 Cloudflare Worker Secret 和 GitHub Secret 存在，绝不出现在仓库、Markdown 或浏览器。
